# Перенос

Упаковщик небольших Python-проектов для запуска на другом компьютере. Читает исходники без выполнения и собирает ZIP с кодом, данными, списком зависимостей и инструкцией запуска.

**Стек:** Python, FastAPI, React, Vite. База данных не нужна.

## Запуск

Нужны Python 3.12+ и Node.js 22.12+. Проверено на Python 3.14 и Node.js 26.

```sh
git clone https://github.com/apvpw/project.git
cd project
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
npm --prefix frontend ci
npm --prefix frontend run build
python run.py
```

Откройте **http://127.0.0.1:8000**. При следующих запусках достаточно активировать `.venv` и выполнить `python run.py`.

В Windows используйте `python` вместо `python3`, а для активации окружения в PowerShell — `.venv\Scripts\Activate.ps1`.

Для сжатых RAR нужен распаковщик в PATH: `unrar`, `unar`, 7-Zip или `bsdtar`. Например, `brew install unar` на macOS или `sudo apt install unar` на Ubuntu. Для ZIP и обычных папок он не нужен.

## Как пользоваться

1. Нажмите «Выбрать проект». Добавьте папку, ZIP/RAR или отдельные `.py` вместе с локальными модулями и примером данных. Проверьте появившееся дерево файлов.
2. Нажмите «Проверить зависимости». Проверьте внешние библиотеки и уточните неизвестные пакеты. Стандартные и локальные модули устанавливать через pip не нужно.
3. Перейдите к скачиванию, проверьте команду запуска и скачайте ZIP. Dockerfile можно включить в разделе «Дополнительно».
4. Распакуйте ZIP в отдельную папку и выполните команды из README. Результат проверки можно записать в REPORT.md.

Шкала сверху показывает завершённые этапы подготовки пакета. Успешный запуск проверяется отдельно, после скачивания.

Внутри пакета:

```text
project/
├── main.py
├── data/
├── README.md         # Установка и запуск
├── requirements.txt  # Зависимости или их черновик
├── REPORT.md         # Предупреждения и результат проверки
└── Dockerfile        # Если включён при сборке
```

Исходная структура сохраняется. Если README, requirements или Dockerfile уже были в проекте, их прежние версии переносятся в `originals/`. При занятом имени используется `originals-2/` и далее. Файлы с признаками секретов по умолчанию исключаются; их список виден в отчёте.

## Примеры для проверки

Готовые архивы находятся в [examples/archives](examples/archives). Скачайте их и загрузите в сервис.

| Архив | Что проверяет | Ожидаемый результат |
| --- | --- | --- |
| [data_analysis.zip](examples/archives/data_analysis.zip) | numpy, pandas, чтение CSV | Выручка `1500.00`, среднее `375.00`, файл `result.csv` |
| [local_modules.zip](examples/archives/local_modules.zip) | Локальный `helpers.py` и стандартная библиотека | 19 слов, 15 уникальных; внешние пакеты не нужны |

Исходники лежат рядом, в `examples/data_analysis/` и `examples/local_modules/`. Данные вымышленные. В примерах нет закреплённых версий библиотек: они показывают случай, когда сервис готовит черновик requirements.

Результаты запуска обоих пакетов в отдельных чистых venv: [tests/VERIFICATION.md](tests/VERIFICATION.md).

## Как устроен проект

```text
backend/
  main.py             HTTP-запросы и временные загрузки
  archive.py          Чтение файлов, ZIP/RAR, проверка путей и исходников
  analyzer.py         Разбор AST, импорты, точки входа и предупреждения
  dependencies.py     Файлы зависимостей и соответствия модуль → пакет
  registry.py         Подсказки неизвестных пакетов через API PyPI
  generator.py        README, requirements, отчёт, Dockerfile и итоговый ZIP
  models.py           Модели анализа и настроек
  requirements.txt
frontend/
  src/App.jsx         Состояние проекта и переходы между этапами
  src/api.js          Запросы к серверу
  src/components/     Загрузка, дерево файлов, зависимости и скачивание
  src/styles.css      Оформление
examples/             Два проекта и архивы для загрузки
tests/                Тесты, проверка примеров и её результаты
tools/
  environment_report.py  Добровольный снимок локальной среды
run.py                Запуск собранного сайта
```

Загрузка проходит проверку, затем анализатор обходит AST и собирает импорты. Модули сопоставляются со стандартной библиотекой, файлами проекта и известными названиями пакетов. После уточнений пользователя генератор собирает файлы и ZIP. Исходники пользователя не импортируются и не запускаются.

## Зависимости и версии

Читаются `requirements.txt`, `requirements.in`, файлы `requirements-dev.txt` и подобные, стандартные зависимости и дополнительные группы в `pyproject.toml`, а также `environment.yml`. Из дополнительных групп включаются пакеты с найденными импортами; неиспользуемые инструменты разработки не добавляются. Основная группа имеет приоритет. Poetry и зависимости по URL требуют ручного уточнения. Conda-зависимости сохраняются отдельно и не превращаются в пакеты pip автоматически.

Сначала используются файлы проекта и каталог известных соответствий. Он учитывает отличия вроде `pytest_asyncio → pytest-asyncio`, варианты OpenCV и namespace-пакеты вроде `google.cloud.storage`. Неизвестные имена проверяются через [JSON API PyPI](https://docs.pypi.org/api/json/). Найденный пакет показывается как подсказка: его нужно подтвердить, потому что имя импорта не всегда совпадает с именем дистрибутива. До подтверждения он не попадёт в requirements.

В PyPI отправляются только названия неизвестных импортов. Импорты из файлов с обнаруженными признаками секретов не отправляются; пакет нужно указать вручную. Пакеты не скачиваются и не устанавливаются. До 30 имён проверяются за один анализ, поиск ограничен пятью секундами, успешные ответы и отсутствие пакета кешируются на час. Без сети работает локальный анализ; неизвестные пакеты остаются для ручного уточнения. Отсутствие имени в PyPI не означает, что библиотека не существует: она может быть приватной или устанавливаться другим способом.

По `import pandas` нельзя узнать версию pandas. Если версия указана в файле зависимостей, она сохраняется. Иначе поле остаётся пустым; известное ограничение можно вписать вручную, например `==2.2.3` или `>=2,<3`. Команда запуска и нижняя граница версии Python по синтаксису также требуют проверки.

Отмечаются динамические импорты, некоторые отсутствующие данные и переменные окружения, признаки секретов, отсутствие README и LICENSE. Проверки не гарантируют, что найдены все зависимости, данные и секреты.

Если исходный проект работает у автора, в его Python-окружении можно выполнить скрипт из этого репозитория:

```sh
python tools/environment_report.py
```

Скрипт можно также скачать на первом экране, в разделе «Версии среды». Он создаст `environment-report.json` с версией Python, установленными пакетами и соответствиями импортов из их метаданных. Это позволяет распознавать библиотеки, которых нет в каталоге сервиса. Файл можно приложить при загрузке. Переменные окружения и содержимое исходников не собираются, скрипт ничего не отправляет по сети. Версии видны рядом с полями зависимостей; кнопка «Подставить версию» переносит выбранную версию в requirements. Самостоятельно сервис их не закрепляет.

## Проверки

Из корня проекта, с активной `.venv`:

```sh
python -m pip install -r tests/requirements.txt
python -m unittest discover -s tests -v
python -m tests.verify_examples
```

Последняя команда создаёт два временных venv, устанавливает зависимости и запускает только подготовленные примеры. Для numpy/pandas нужен интернет. Результаты записываются в `tests/VERIFICATION.md`, временные окружения удаляются.

## Разработка

В двух терминалах:

```sh
python -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

```sh
npm --prefix frontend run dev
```

Откройте адрес Vite, обычно http://127.0.0.1:5173. Запросы `/api` перенаправляются на FastAPI. Live Server для этого проекта не используется.

## Ограничения

- До 20 МБ на загрузку и 5 МБ на файл. До 100 отдельных файлов, включая выбор папки; до 500 файлов и 50 МБ после распаковки архива.
- В загрузке нужен хотя бы один читаемый `.py`. Изображения, аудио и другие файлы рядом с кодом сохраняются. Ошибки синтаксиса показываются как предупреждения.
- `.git`, `.venv`, `node_modules` и кэш пропускаются. Небезопасные пути, ссылки, зашифрованные и многотомные архивы отклоняются.
- Python-файлы больше 1 МБ сохраняются без AST-разбора, с предупреждением.
- Сервер работает в одном процессе. До восьми загрузок хранятся в памяти не дольше 30 минут; «Новый проект» удаляет текущую. При чтении RAR распаковщик может использовать системные временные файлы.

Сервис готовит стартовый пакет, а не восстанавливает среду с гарантией. Системные библиотеки, сетевые ресурсы, оборудование и совместимость версий нужно проверять отдельно. Dockerfile — начальный шаблон. Проверка в venv подтверждает запуск в конкретном окружении, но не делает неизвестный код безопасным.
